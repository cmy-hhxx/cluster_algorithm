# 归类任务

你的任务：读一批「AI 回答失败」的归因条目，给每条选**一个**类别。

## 1. 输入

每行一个 JSON，字段如下：

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `seq` | 编号 | 输出时原样带回 |
| `component` | 失败发生在链路的哪个环节 | 流水线已按它分组，你不需要判断环节 |
| `label` | 上游模型给这条起的名字 | 只作线索，**不要按字面关键词分类** |
| `definition` | 这条到底错在哪 | 主证据 |
| `reason` | 为什么这么判、有什么证据 | 主证据，用来区分机制 |

文本可能被截断；以现有内容为准，不要脑补。

## 2. 怎么判（按顺序，命中即停）

1. 看这个环节本来该做的动作，停在哪一步（下表）。环节不用你判断，`component` 已经定了。
2. 在同一个机制下，按「失效动作 + 对象」选唯一类别。
3. 两个类别都说得通时，选**更早失效**的那个；仍不确定就标 `uncertain=true`，但必须给出一个结论。

| 代码 | 机制 | 判据 |
|---|---|---|
| M1 | 空转未执行 | 没有产出任务所需的最小动作 |
| M2 | 目标错配 | 动作发生了，对象/指标/时段/范围/语义不对 |
| M3 | 执行失败 | 动作在执行层面失败（报错/超时/零行/空返回/截断） |
| M4 | 结果不可用 | 有返回，但内容撑不起任务（不相关/样板/过期/缺字段） |
| M5 | 加工计算错误 | 数据对，但换算/聚合/口径/比较错 |
| M6 | 无依据断言 | 结论缺乏证据，或与已有证据矛盾 |
| M7 | 交付不符 | 形式与完整性不达标（缺项/格式/语言/答非所问） |

## 3. 边界裁决（出现分歧时以此为准）

| 情形 | 判 | 不判 |
|---|---|---|
| 规划把整句问话当查询下发，下游解析失败 | M2（规划） | M3（执行） |
| 查询条件正确、市场恰好无数据、返回 0 行 | 零行无诊断 | 条件写死 |
| 返回列少了请求的字段，状态仍成功 | M4 | M2 |
| 请求指标被换成同名不同义字段 | M2 | M4 |
| 多源数值互相矛盾、未标优先级 | M4 | M5 |
| 拿到旧快照但没标注时点 | M4（时效） | M5 |
| 拿到正确数据但期间算错 | M5 | M4 |
| 材料完整却给出无来源数字 | M6 | M5 |
| 取数失败被写成「该股无风险」 | M6 | M3 |
| 图未渲染却写「见下图」 | M7 | M3 |
| 同一会话里两条问题因果相连 | 各归各的 | 合并 |

## 4. 三条硬规则

1. **一条只选一个类别**，不许新造类别 id。
2. **没有「其他」类别**。确实没有合适的，选最接近的，标 `uncertain=true`，但不要自造。
3. **不因为某个类别大就绕开它**，也不把不相干的条目塞进去凑数。

## 5. 输出

只输出与输入等量的 JSONL，每行一个对象：

```json
{"seq": 12, "path": "S3.M4.1", "uncertain": false}
```

- `path` 必须是下方「类别清单」里的 id，格式为 `S<环节>.M<机制>.<序号>`。
- `uncertain`：两个类别都能自圆其说时填 `true`，有把握填 `false`。它不影响归属，只用于人工复核。
- 不要解释，不要代码块，不要多余字段。
