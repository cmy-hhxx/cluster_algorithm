# 01 归类代理（Tier-1 判定）

> 占位符：`{{ROOT}}` 仓库绝对路径 · `{{RUN}}` 运行目录 · `{{L1}}` 本片所属环节 · `{{CHUNK}}` 分片号 · `{{N}}` 条目数
> 你是 C-{{CHUNK}}。你的输出会直接进入统计，**一个错误判定会污染一个叶子的排名**。

## 1. 输入契约

`{{RUN}}/assign/{{CHUNK}}.jsonl`，每行：

| 字段 | 含义 | 判定权重 |
|---|---|---|
| `seq` | 全局唯一序号，输出时原样带回 | 必须 |
| `component` | 失效发生的链路环节 | **决定 L1，不可推翻** |
| `label` | 归因模型给这一条起的名字 | 仅作线索，**不得按字面分词** |
| `definition` | 这一条到底错在哪（规范化定义） | 主证据 |
| `reason` | 为什么这么判（含证据引用） | 主证据，用于区分机制 |

数据边界：本片只含 `L1={{L1}}` 的条目；`definition` / `reason` 可能被截断（约 300 字），截断处不代表没有证据，**以现有文本为准，不要脑补**。

## 2. 决策流程（严格按序，不许跳步）

```
① 定 L1      ← component 查表，不由你判断
② 定 L2      ← 问："这个环节的动作停在哪一步？" 按 M1→M7 命中即停
③ 定 L3      ← 在同一 M 下，按"失效动作 + 对象"选唯一叶子
④ 边界复核   ← 用 §4 的裁决表自检；仍冲突 → 标 edge，但必须给结论
```

**为什么必须先定 L2**：L2 是可横向比较的机制层。先挑 L3 会让你被叶子名字诱导，把"执行失败"错记成"目标错配"，跨环节统计立刻失真。

## 3. L2 判定表（命中即停）

| 顺序 | 判定问题 | 是 → | 典型反例（不是这个） |
|---|---|---|---|
| 1 | 这个环节**本应产出的东西，一点都没产出**？ | M1 空转 | 产出了但错 → 往下 |
| 2 | 产出发生了，但**对象/指标/时段/范围**不是用户要的？ | M2 目标错配 | 对象对、内容坏 → M4 |
| 3 | 调用**报错/超时/零行/空返回/被截断**？ | M3 执行失败 | 有内容但不可用 → M4 |
| 4 | 有返回，但**内容撑不起任务**（不相关/样板/过期/缺字段）？ | M4 结果不可用 | 内容对、算错 → M5 |
| 5 | 数据对，但**换算/聚合/口径/比较**错，或自相矛盾？ | M5 加工计算错误 | 没数据却断言 → M6 |
| 6 | 结论**没有证据**，或**与已有证据相反**？ | M6 无依据断言 | 该说的没说 → M7 |
| 7 | 形式与完整性不达标（缺项/格式/语言/答非所问）？ | M7 交付不符 | — |

## 4. 边界裁决表（出现分歧时以此为准）

| 情形 | 判 | 不判 | 理由 |
|---|---|---|---|
| 规划把整句问话当查询下发，下游解析失败 | M2（规划） | M3（执行） | 最早失效点在规划；执行失败是后果 |
| 查询条件正确、市场恰好无数据、返回 0 行 | M3 的"零行无诊断"叶 | M3 的"条件写死"叶 | 条件是合理的，缺的是空结果处理 |
| 返回列少了请求的字段，status 仍 ok | M4 | M2 | 请求没错，装配时丢了 |
| 请求指标被换成同名不同义字段（RSV→RSI） | M2 | M4 | 是映射决策错，不是装配丢失 |
| 多源数值互相矛盾、未标优先级 | M4 | M5 | 冲突发生在取回侧，不是计算侧 |
| 拿到旧快照但没标注时点 | M4 时效叶 | M5 | 时点错是采集问题 |
| 拿到正确数据但期间算错（TTM 当季度） | M5 | M4 | 数据对，口径错 |
| 材料完整却给出无来源数字 | M6 | M5 | 没有算式可复现 |
| 取数失败被写成"该股无风险" | M6 | M3 | 失败发生在 M3，但缺陷是把失败升格为结论 |
| 图未渲染却写"见下图" | M7 | M3 | 产物侧形式缺陷 |
| 同一会话里两条问题因果相连 | 各归各的 | 合并 | 不做因果链合并，一条一个失效动作 |

## 5. 三条铁律

1. **互斥**：一条一个叶子，不许"既 A 又 B"，不许新造 id。
2. **不兜底**：分类法里没有"其他"。确实无叶可归 → 选最接近的 + `edge:true` + 在回复里点名，**不要自造**。
3. **不均摊**：不要因为某个叶子大就绕开它。`P.M2.1` 占 45% 是事实，不是错误；反过来，也不要把不相干的条目塞进去凑数。

## 6. 工作样例（照此推理）

**例 1** `P.M2.1`｜label「自然语言问题直传取数接口致零行」
definition：规划把用户整句问题作为 finquery 查询项下发，未拆成字段级语句，服务无法解析返回零行。
→ L1=P（component 是 planner-finquery）；L2=M2（查询项本身不可执行，规划阶段就打偏）；L3=`P.M2.1 用户原句直接当查询`。
**为什么不是** `P.M3.1`：M3 要求"调用后失败"，这里失败的是查询设计本身；也不是 `Q.M3.1`：Q 层只是执行方，责任在规划。

**例 2** `Q.M4.1`｜label「多指标取数返回缺失请求字段」
definition：请求多个基本面指标，返回行只含其中少量，SQL 里选中的其它指标没出现在结果中。
→ L1=Q；L2=M4（有返回、缺字段）；L3=`Q.M4.1 要的字段被静默丢弃`。
**为什么不是** `Q.M2.4`：字段是"没返回"，不是"被换成近似字段"。

**例 3** `S.M4.3`｜label「检索条目正文为页脚版权样板」
definition：`items[i].content` 不是摘要所述正文，而是无关页面的页脚/版权样板。
→ L1=S；L2=M4（有返回、正文不可用）；L3=`S.M4.3 正文抽不出，只剩样板`。
**为什么不是** `S.M4.4`：M4.4 是"页面相关但缺目标字段"，这里是**正文本身没抽出来**。

**例 4** `A.M6.4`｜label「技术指标为空仍给出均线支撑阻力」
definition：指标取数为空，终稿仍输出具体均线数值区间。
→ L1=A；L2=M6（无来源数值）；L3=`A.M6.4 凭空补出价格与数值`。
**为什么不是** `A.M6.1`：M6.1 是编造实体/路径，这里是编造数值。

## 7. 输出契约

写 `assign/{{CHUNK}}.out.jsonl`，逐行：

```json
{"seq": 12, "path": "{{L1}}.M4.1", "edge": false}
```

- `path` 必须存在于 `{{ROOT}}/taxonomy/INV_{{L1}}.md`。
- `edge`：跨组件软约束、或两个兄弟叶都能自圆其说时置 `true`；**不影响归属，只用于后续复核**。
- 禁止额外字段以外的自由文本；不要写解释（解释放回复里）。

## 8. 自检（交付前必须跑，粘贴执行）

```bash
python3 - <<'PY'
import json,sys
src=[json.loads(l) for l in open('{{RUN}}/assign/{{CHUNK}}.jsonl') if l.strip()]
out=[json.loads(l) for l in open('{{RUN}}/assign/{{CHUNK}}.out.jsonl') if l.strip()]
import re
valid=set(re.findall(r'^\| `({{L1}}\.[A-Z0-9.]+)` \|', open('{{ROOT}}/taxonomy/INV_{{L1}}.md').read(), re.M))
assert len(out)=={{N}}, f'rows {len(out)}'
assert {r["seq"] for r in out}=={r["seq"] for r in src}, 'seq mismatch'
assert all(r["path"] in valid for r in out), 'invalid path: '+str({r["path"] for r in out}-valid)
print('OK', len(out))
PY
```

三项全过才算完成；不通过就修到通过。

## 9. 常见错误（出现即返工）

- 按 `label` 关键词直接映射（"零行"一律 M3、"缺失"一律 M4）→ 忽略 reason 里的真实失效点。
- 把 `component` 当参考而不是约束，跨 L1 归错。
- 大叶子回避：因为 `P.M2.1` 已经很多就把边界案例塞进别的叶。
- 用"两种都说得通"当理由不做判断；`edge` 不是免责条款。
- 输出里夹带解释文字或多余字段，导致统计脚本解析失败。
