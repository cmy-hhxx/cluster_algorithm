# 环节 S1：取数规划

把问题翻译成结构化取数请求的阶段。含 planner-finquery。失效多为查询项构造错、实体/时点/指标设计错。

## 0. 判定骨架（按顺序问，命中即停）

1. **这一环该做的动作，一点都没做？** → `S1.M1.1` 取数零查询 / `S1.M1.2` 追问未重新取数 / `S1.M1.3` 取数计划未执行
2. **动作做了，但对象/指标/时段/范围不是用户要的？** → `S1.M2.1` 取数查询照抄原句 / `S1.M2.10` 取数排序设置错 / `S1.M2.11` 取数查询重复 / `S1.M2.2` 取数标的认错 / `S1.M2.3` 取数查询写入臆造实体 / `S1.M2.4` 取数时间窗锚错 / `S1.M2.5` 取数字段取了近似指标 / `S1.M2.6` 取数漏掉数据维度 / `S1.M2.7` 取数过滤条件加错 / `S1.M2.8` 取数查询过泛 / `S1.M2.9` 取数意图判错
3. **调用报错/超时/零行/空返回/被截断？** → `S1.M3.1` 取数计划被截断 / `S1.M3.2` 取数调用返回空
6. **结论没证据，或与已有证据相反？** → `S1.M6.1` 未取数即下结论

> 同一环节内，先定机制，再选类别。跨机制的类别不互斥，靠本节顺序裁决。

## 2. 类别判定卡（用来区分互斥）

### `S1.M1.1` 取数零查询  ·  129 条 / 111 会话

- **定义**：面对需要数据支撑的请求，规划输出空数组或判定“无需检索”，本轮零查询下发，链路在规划处断流。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：计划输出为 [] / 空 search 项；本轮无工具调用
- **纳入**：输出为 [] / 空 search 项 / 明确判定无需外部材料；下游只能用旧上下文或通用知识作答。
- **排除**：计划里有查询但执行侧未派发 → S1.M1.3；计划有查询但执行报错 → S1.M3.1。
- **最相近的类别**：`S1.M1.3` — 区分点：出现查询项但没被执行 → M1.3；压根没有查询项 → 本叶
- **标签**：缺失 ｜ **组件**：planner-finquery
- **正例**：seq=7349「取数规划子模型对汇率查询返回空计划」；seq=6073「取数规划输出空数组未规划任何数据查询」
- **反例（属 `S1.M1.3`，不属本叶）**：seq=9774「finquery 计划混入开放式问题致该条查询未执行」

### `S1.M1.2` 追问未重新取数  ·  35 条 / 33 会话

- **定义**：多轮追问或核对轮次中，最新请求已指向新的标的/价位，规划仍输出空计划，直接复用历史数字或截图信息。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：session_round>1；计划为空；答案沿用历史数字或截图
- **纳入**：session_round>1、追问语义明确要求新数据，但计划为空且回答沿用旧值。
- **排除**：首轮空计划 → S1.M1.1；计划非空但查错对象 → S1.M2.2。
- **最相近的类别**：`S1.M1.1` — 区分点：首轮空计划 → M1.1；追问轮仍空 → 本叶
- **标签**：时效,缺失 ｜ **组件**：planner-finquery
- **正例**：seq=4024「finquery 取数规划返回空计划」；seq=5106「finquery 规划输出空计划，未规划任何取数」
- **反例（属 `S1.M1.1`，不属本叶）**：seq=7349「取数规划子模型对汇率查询返回空计划」

### `S1.M1.3` 取数计划未执行  ·  6 条 / 6 会话

- **定义**：计划内容本身正确，但条目数超出执行侧派发能力或多查询塞进单项，排在后面的查询从未被调用。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：计划文本含 N 条查询，执行记录 < N
- **纳入**：计划文本里有的查询，执行记录里找不到对应调用。
- **排除**：计划为空 → S1.M1.1；派发后返回空 → S1.M3.1。
- **最相近的类别**：`S1.M3.1` — 区分点：执行了但返回空 → M3.1；根本没执行 → 本叶
- **标签**：缺失 ｜ **组件**：planner-finquery
- **正例**：seq=9774「finquery 计划混入开放式问题致该条查询未执行」；seq=6102「取数规划结构化规格未进入实际查询」
- **反例（属 `S1.M3.1`，不属本叶）**：seq=5143「finquery 请求退化为无界重复且未闭合的 ETF 列表」

### `S1.M2.1` 取数查询照抄原句  ·  1440 条 / 851 会话

- **定义**：把用户整句问句、口语陈述、操作指令或裸实体名直接写成一条 finquery 查询项，既无标的标识也无指标与时间范围，取数侧只能按字面猜语义。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：查询 content 与用户问句高度重合，无标的/指标/时间要素
- **纳入**：查询 content 与用户原句高度重合、缺少字段/时间/标的要素；常伴随后续解析异常或全市场无过滤结果。
- **排除**：查询要素齐全但选错字段 → S1.M2.5；查询可执行但返回不相关 → Q 层对应叶。
- **最相近的类别**：`S1.M2.5` — 区分点：有结构化要素但选错字段 → M2.5；整句原样透传 → 本叶
- **标签**：缺失 ｜ **组件**：planner-finquery
- **正例**：seq=10395「取数规划输出混入原始问句，生成非法 finquery 查」；seq=3718「取数规划把用户口语原句直接当作 finquery 查询项」
- **反例（属 `S1.M2.5`，不属本叶）**：seq=6870「取数规划排序字段与数据源不匹配（sentiment 指标缺字」

### `S1.M2.2` 取数标的认错  ·  212 条 / 154 会话

- **定义**：查询中的标的与用户所指不一致：裸代码缺交易所/市场限定、拼写错误、资产类别误判、同名或近义代码未归一化。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：查询里的代码/名称与用户所指不一致；裸代码无交易所后缀
- **纳入**：含 NER 把交易所名当股票、把 GOLD 解析为 GLD、跨市场同名。
- **排除**：查询里出现用户没提过的实体（凭空写入）→ S1.M2.3。
- **最相近的类别**：`S1.M2.3` — 区分点：实体来自输入但解析错 → 本叶；输入里没有的实体 → M2.3
- **标签**：实体 ｜ **组件**：planner-finquery
- **正例**：seq=11590「歧义短串未做实体归一化即转成 finquery 查询词，」；seq=9348「取数查询未限定交易所/证券代码导致同名标的取错市场」

### `S1.M2.3` 取数查询写入臆造实体  ·  25 条 / 24 会话

- **定义**：查询串出现输入不支持的平台、品牌、公司、画像或前提，或把用户给定约束改写得更强/更弱，检索围绕未证实对象展开。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：查询出现输入未提及的品牌/平台/前提，或约束被改写
- **纳入**：含把助手自述假设固化进查询、把“某概念”扩写成具体产品代次。
- **排除**：实体来自用户但被解析错 → S1.M2.2。
- **最相近的类别**：`S1.M2.2` — 区分点：实体在输入里但解析错 → M2.2；凭空写入 → 本叶

### `S1.M2.4` 取数时间窗锚错  ·  101 条 / 88 会话

- **定义**：查询的日期/时段锚点与请求时点或用户窗口不一致：锚到非交易日、过期月份季度、未解析的相对时间，或把区间收窄/放宽。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：查询日期≠目标日期；锚到非交易日/过期月份
- **纳入**：含缺年份日期落到上一年、YTD 未覆盖年初、快照日选在未来。
- **排除**：锚点正确但返回旧页面 → S 层时效叶；期间口径算错 → M5。
- **最相近的类别**：`S1.M2.6` — 区分点：时间对但维度缺 → M2.6；时间整体错 → 本叶
- **标签**：时效 ｜ **组件**：planner-finquery
- **正例**：seq=8214「取数日期钉在未来交易日导致 finquery 零行」；seq=3554「取数查询硬编码日期窗口越界，返回零行」
- **反例（属 `S1.M2.6`，不属本叶）**：seq=10203「取数查询遗漏用户明确要求的供应/稀释维度」

### `S1.M2.5` 取数字段取了近似指标  ·  126 条 / 111 会话

- **定义**：标的正确，但请求的指标/字段与用户所需口径不符：近似指标顶替本体指标、缺支撑结论的必需字段、请求不存在的字段。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：查询字段与用户指标名近义不同义（52周高低→日内高低）
- **纳入**：含 52 周高低→日内高低、总收益→单日涨跌、RSV→RSI、上行空间→目标价变动率。
- **排除**：字段在 SQL 生成/返回时被丢弃 → S3.M4.1；整个维度未规划 → S1.M2.6。
- **最相近的类别**：`S1.M2.1` — 区分点：整句透传 → M2.1；有字段但选错 → 本叶
- **标签**：口径 ｜ **组件**：planner-finquery
- **正例**：seq=6870「取数规划排序字段与数据源不匹配（sentiment 指标」；seq=11658「finquery 行情取数零结果/字段与库表不匹配」
- **反例（属 `S1.M2.1`，不属本叶）**：seq=10395「取数规划输出混入原始问句，生成非法 finquery 查询」

### `S1.M2.6` 取数漏掉数据维度  ·  65 条 / 60 会话

- **定义**：查询集存在但未覆盖任务必需维度或对象：期权链/权利金、实时现价、技术指标与 N 日区间、多标的中的其余标的、并列分支、完整名单、用户给定地域/排除/价格约束。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）

- **最相近的类别**：`S1.M2.5` — 区分点：少一个字段 → M2.5；少一整类 → 本叶

### `S1.M2.9` 取数意图判错  ·  52 条 / 47 会话

- **定义**：把用户问题判成另一类任务或路由到不匹配的来源（咨询→客服工单、数量问题→选股、结构化筛选→网页检索），或改写时改变问题指向、丢失限定。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：路由到不匹配的任务类型或数据源（咨询→选股、筛选→网页）
- **纳入**：含把开放式问题收窄为当日选股、把复核请求判为行情播报。
- **排除**：意图正确但对象错 → S1.M2.2。
- **最相近的类别**：`S1.M2.6` — 区分点：类别对但漏维度 → M2.6；类别判错 → 本叶
- **标签**：口径 ｜ **组件**：planner-finquery
- **正例**：seq=4907「自然语言意图问题被当作 finquery 结构化查询下发」；seq=8634「生成与本轮问题无关的选股查询」
- **反例（属 `S1.M2.6`，不属本叶）**：seq=10203「取数查询遗漏用户明确要求的供应/稀释维度」

### `S1.M3.1` 取数计划被截断  ·  3 条 / 3 会话

- **定义**：计划 JSON 在输出完成前被 token 上限或推理循环截断，查询不完整。
- **可观测信号**：计划 JSON 不完整/被截断；调用返回 null 或零条
- **纳入**：计划 JSON 不完整、被截断、或调用结果为空对象。
- **排除**：计划完整但未派发 → S1.M1.3。
- **最相近的类别**：`S1.M3.2` — 区分点：取数计划被截断 → 本叶；取数调用返回空 → S1.M3.2
- **标签**：失败 ｜ **组件**：planner-finquery
- **正例**：seq=5143「finquery 请求退化为无界重复且未闭合的 ETF 」；seq=8「finquery 计划输出截断，生成非法 JSON 请求」
- **反例（属 `S1.M3.2`，不属本叶）**：seq=8530「取数查询零行空返回」

### `S1.M3.2` 取数调用返回空  ·  127 条 / 114 会话

- **定义**：计划已下发，但调用返回 null / 零条 / 无任何输出。
- **可观测信号**：计划已下发，但调用返回 null / 零条 / 无任何输出。
- **纳入**：仅收 取数调用返回空 这一类；具体现象见 definition。
- **排除**：若属于「取数计划被截断」→ S1.M3.1。
- **最相近的类别**：`S1.M3.1` — 区分点：取数调用返回空 → 本叶；取数计划被截断 → S1.M3.1
- **标签**：失败 ｜ **组件**：planner-finquery
- **正例**：seq=8530「取数查询零行空返回」；seq=10832「取数规划下发零结果查询」
- **反例（属 `S1.M3.1`，不属本叶）**：seq=5143「finquery 请求退化为无界重复且未闭合的 ETF 列表」

### `S1.M6.1` 未取数即下结论  ·  6 条 / 4 会话

- **定义**：在检索/取数尚未返回或返回为空时，规划输出即给出确定性判断（反转信号、止损覆盖、税率适用），且与已有记录或后续数据矛盾。（本叶仅收 planner-finquery 取数规划子模型 产生的缺陷）
- **可观测信号**：规划正文含确定性断言，且此时无任何工具结果
- **纳入**：规划正文/计划注释里出现无需证据的结论性断言。
- **排除**：结论出现在终稿 → A 层 M6 叶。
- **最相近的类别**：`S1.M1.1` — 区分点：空计划且无结论 → M1.1；空计划还下结论 → 本叶
- **标签**：编造 ｜ **组件**：planner-finquery
- **正例**：seq=2814「取数规划子模型越位直接作答、未产出取数计划」；seq=10180「取数规划轮未经工具核验即写出具体支持渠道，且与同轮工具返」
- **反例（属 `S1.M1.1`，不属本叶）**：seq=7349「取数规划子模型对汇率查询返回空计划」
