## 空格位（不设叶子）及归属

| 格子 | 为什么不需要 |
|---|---|
| `S1.M7` | 规划层没有独立交付物；请求的形式/缺项落在 S10（请求生成），终稿呈现落在 S9.M7。 |
| `S12.M4` | 编排产出不可用（结构损坏/解析失败）由 S12.M3.1 承接，不另立 M4。 |
| `S12.M7` | 编排交付缺项由 S12.M2.2（漏必要步骤）承接，不另立 M7。 |
| `S2.M7` | 同上；检索请求的完整性由 S2.M2 的「漏掉覆盖维度/时效锚点错」承接。 |
| `S3.M7` | 取数回执的缺字段、缺时点、被截断由 S3.M4（结果不可用）承接，不单列交付形式。 |
| `S5.M2` | 抓错对象/抓到无关页由 S5.M4.1（搜回错误对象）承接；检索词本身写错在 S2.M2。 |
| `S5.M5` | 检索执行层不做换算与聚合，数值口径错落在 S9.M5。 |
| `S5.M6` | 「没检索就断言」在规划层是 S2.M6，在合成层是 S9.M6，不在执行层。 |
| `S5.M7` | 网页内容的引用/呈现问题落在 S9.M7，S5 只承接「取不到/取错」。 |
| `S6.M1` | 该调没调是编排/规划层的决定（S12.M1、S2.M1），S6 只在调用发生之后承接缺陷。 |
| `S6.M2` | 发给客服的 query 写错主体属于请求生成（S10.M2），S6 承接回执侧（S6.M4）。 |
| `S6.M5` | 客服返回的是文本规则/操作说明，不做加工计算；按规则算错落在 S9.M5。 |
| `S7.M2` | 记忆检索的主体写错属于请求生成（S10.M2）；S7 承接回执侧（S7.M4.1 记忆读写错）。 |
| `S7.M5` | 记忆内容不参与计算；基于记忆的数值推算错落在 S9.M5。 |
| `S7.M6` | 没读到记忆却断言用户历史属于编造，落在 S9.M6.1（编造不存在的对象）。 |
| `S7.M7` | 记忆写入的回执缺失/内容不符由 S7.M4.1 承接。 |
| `S8.M7` | 识图/技能输出缺项由 S8.M4.1（正文被截断）与 S8.M5（识读结果错）承接。 |

## 维护约定

1. 一格里要不要有叶子，看**这一环节能不能独立承接该机制的缺陷**，不是看矩阵好不好看。
2. 已观察到模型在真实数据里索要某格（日志 `bad paths ['Sx.My.z']`）→ 优先补叶，别急着登记不适用。
3. 登记不适用必须写明「落到哪个叶」，否则缺陷会变成没人认领的悬挂项。
