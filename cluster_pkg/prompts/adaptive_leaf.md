# 自适应新叶归纳（三轴分类法 L3 扩充）

你的任务：在环节 `{{L1}}`（{{L1_NAME}}）中，有一批归因条目经复核后无法落入任何现有叶子。请审视这批条目：
1. 若某条实质上可被某个**现有叶子**准确覆盖，直接指派到该现有叶子 id；
2. 若确属现有叶子均未覆盖的真实失效模式，在 `{{L1}}` 下遵循三轴规范归纳 **1 个或多个互斥的新 L3 叶子**，并将对应条目指派过去。

## 1. 本环节与七种机制定义

- 当前环节：`{{L1}} {{L1_NAME}}` —— {{L1_DEF}}
- 机制判定优先级（按 M1 → M7 取最早失效点）：
  - `M1` 空转未执行：该环节没有产出任务所需的最小动作
  - `M2` 目标错配：动作发生了，但对象/指标/时段/范围/语义不对
  - `M3` 执行失败：报错、超时、非零退出、零行、空返回、截断
  - `M4` 结果不可用：有返回，但内容不相关、样板、过期、缺字段
  - `M5` 加工计算错误：数据对，但换算/聚合/口径/比较错或自相矛盾
  - `M6` 无依据断言：结论缺乏证据，或与已有证据矛盾
  - `M7` 交付不符：形式与完整性不达标（缺项/格式/语言/答非所问）

## 2. 本环节现有叶子（新叶必须与它们严格互斥）

{{EXISTING_LEAVES}}

## 3. 新叶准入硬约束（违反任一条均不合法）

1. **严禁兜底桶**：`name` 与 `exclude` 中严禁出现“其他 / 其它 / 杂项 / 未知 / miscellaneous”，`name` 不超过 16 字，不用“与/或”拼凑两个概念，且不得与全库已有叶子重名。
2. **可派工**：名称与定义必须直指具体的失效动作与对象（例如“编排加工计算错”“图像识读结果错误”）。
3. **显式互斥**：`exclude` 必须写明易混边界，并指向本环节具体的既有叶子 id（如 `→ Sx.My.z`）。
4. **合法标签**：`tags` 只能从 `[{{ALLOWED_TAGS}}]` 中选 1–2 个。
5. **判别卡要素齐全**：必须同时给出 `sig`（可观测信号）、`near`（本环节最相近的既有叶子 id）、`split`（与 `near` 的一句话区分点）。

## 4. 待归纳/指派的未归类条目（共 {{N}} 条）

## 5. 输出契约

只输出**一个合法的 JSON 对象**（不要解释文字）：

```json
{
  "new_leaves": [
    {
      "key": "NEW_1",
      "l2": "M5",
      "name": "具体失效模式名称",
      "plain": "一句通俗人话解释",
      "definition": "该失效模式的准确定义",
      "include": "哪些具体可观测现象归入本叶",
      "exclude": "相似但不属本叶的情形 → `{{NEAR_EXAMPLE}}`",
      "tags": ["口径"],
      "sig": "日志或轨迹中的可观测信号",
      "near": "{{NEAR_EXAMPLE}}",
      "split": "与最近邻叶的一句话区分规则"
    }
  ],
  "assignments": [
    {"seq": 1, "target": "NEW_1", "edge": false}
  ]
}
```

- `assignments` 必须覆盖输入的全部 {{N}} 个 `seq`，不重不漏；
- `target` 可以是上方 `new_leaves` 里的临时键（如 `"NEW_1"`），也可以是第 2 节中的既有合法叶 id。
